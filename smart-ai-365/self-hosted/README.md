# SMART AI 365 — محرك مستقل

هذا المسار يشغّل نموذج Qwen3 محلياً/على خادم تملكه باستخدام Ollama، دون Google AI Studio أو Groq أو OpenRouter أو Cloudflare AI.

## المتطلبات
- Docker Engine وDocker Compose.
- خادم Linux أو جهاز يعمل باستمرار.
- ذاكرة وموارد مناسبة للنموذج. يبدأ الإعداد بـ Qwen3:8b؛ قد يكون بطيئاً على CPU، ويحتاج ذاكرة أكبر عند رفع حجم النموذج.
- اتصال إنترنت أول مرة لتنزيل صورة Ollama والنموذج.

## التشغيل
1. انسخ هذا المجلد إلى الخادم.
2. اضبط ALLOWED_ORIGIN على أصل الواجهة المنشورة، مثال: https://your-domain.example
3. شغّل: `docker compose up -d --build`
4. تحقق من: `http://SERVER:8000/health`
5. إذا لم يتم تنزيل النموذج تلقائياً، نفّذ: `docker compose exec ollama ollama pull qwen3:8b`
6. اجعل عنوان API في الواجهة هو عنوان هذا الخادم، مع المسار الأساسي فقط؛ الواجهة تضيف `/api/chat`.

## ربط الواجهة
في `smart-ai-365/index.html` عيّن API_URL إلى عنوان الخادم، مثال:
`const API_URL = "https://api.your-domain.example";`

## الأمان قبل النشر العام
- لا تعرض منفذ Ollama 11434 للإنترنت؛ هذا الإعداد لا ينشره على المضيف.
- ضع API خلف HTTPS reverse proxy مثل Caddy أو Nginx.
- أضف مصادقة/حدود معدل الاستخدام وحماية من إساءة الاستخدام قبل فتحه للجمهور.
- اسمح في ALLOWED_ORIGIN بأصل الواجهة الفعلي فقط.
- راقب استهلاك الذاكرة والقرص وحجم تنزيل النموذج.

## التكلفة والحدود
البرمجيات والنموذج مفتوحة المصدر، لكن الجهاز أو الخادم والكهرباء والإنترنت ليست مجانية بالضرورة. لا توجد حصة API خارجية مجانية هنا، لكن الطاقة الاستيعابية والسرعة تعتمد على موارد الخادم. Qwen3:8b نقطة بدء، وليس وعداً بدقة 98%. يجب قياس الدقة باختبارات موثقة لكل لغة ومهمة قبل إطلاق ادعاء جودة.

## توافق API
- GET /health
- POST /api/chat مع مصفوفة messages تحوي role وcontent
- الاستجابة: { "ok": true, "answer": "...", "model": "qwen3:8b" }
