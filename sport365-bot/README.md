# SPORT 365 AI BOT

نواة مستقلة لبوت SPORT 365 تجمع مراقبة مصدر المباريات، وصف الأحداث بالعربية، وإرسال تحديثات وأوامر Telegram. لا تحتوي هذه النسخة على بيانات تجريبية ولا تدّعي وجود بث مباشر قبل ضبط مصدر حقيقي.

## المتطلبات
- Node.js 20 أو أحدث.
- بوت Telegram اختياري عبر BotFather.
- مصدر بيانات مباريات لديك إذن باستخدامه، يعيد JSON بالصيغة أدناه.

## التشغيل
1. انسخ `.env.example` إلى `.env`.
2. أضف `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` عند الرغبة في التنبيهات.
3. أضف `SPORTS_FEED_URL` إلى endpoint موثوق ومصرح به.
4. شغّل `npm start`.

لا ترفع `.env` أو أي مفاتيح إلى GitHub. في الاستضافة استخدم متغيرات البيئة/Secrets.

## واجهة SPORT 365
بعد تشغيل الخدمة على استضافة تدعم Node.js، تتوفر واجهتان للقراءة فقط:
- `GET /api/matches`: حالة الاتصال وآخر المباريات الواردة.
- `GET /api/analysis`: ملخص وصفي لآخر مباراة متاحة، اعتماداً على أحداث المصدر فقط.
- `GET /health`: فحص صحة الخدمة.

لربط موقع GitHub Pages بعنوان الخدمة، ضع عنوان الاستضافة (دون شرطة مائلة أخيرة) داخل وسم `meta` في `sport365/index.html`:
`<meta name="sport365-api" content="https://YOUR-SERVICE-DOMAIN">`
لا تضع أي رمز سري في هذا الوسم أو في ملفات الواجهة. يمكن تقييد CORS عبر المتغير `ALLOWED_ORIGIN` إلى نطاق الموقع.

## أوامر Telegram
- `/start` أو `/help`: المساعدة.
- `/status`: حالة البوت ومصدر البيانات.
- `/matches`: المباريات التي وصلت من المصدر.
- `/analysis`: وصف عربي لآخر مباراة متاحة اعتماداً على أحداث المصدر فقط.

## نقاط مهمة
- هذه نواة تشغيل أولية وليست مزود بيانات رياضية.
- لا يوجد تكامل مفعّل مع GPTFoot أو Match Feed Bot؛ تم بناء وظائف مستقلة لتجنب نسخ شيفرات ذات ترخيص غير مناسب.
- تحليل هذه النسخة وصفي قائم على الأحداث. التحليل التكتيكي المتقدم يحتاج إحصاءات موثوقة مثل التسديدات والاستحواذ والتمريرات والضغط.
- لا تستخدم كشط صفحات أو مصادر غير رسمية قبل مراجعة شروط استخدامها.
- `/health` يعرض فحصاً بسيطاً لصحة الخدمة.
